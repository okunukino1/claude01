# 3本指スクショ (Long Screenshot for Pixel)

OPPO / ColorOS の「長い（スクロール）スクリーンショット」を **Google Pixel** で再現するアプリです。

Pixel 標準にも「キャプチャ範囲を拡大」がありますが、あれは撮影済みの1画面から
**手で範囲を広げる**方式のため、画面数ページ分より長いページは撮れません。
本アプリは**ページを自動でスクロールしながら連続撮影し、1枚の縦長画像に合成**します。
「■ 停止」を押すまで（またはページ最下部まで）いくらでも伸ばせます。

## 機能

| 操作 | 動作 |
|---|---|
| **背面2回タップ（推奨）** | Pixel 標準の「クイックタップ」でスクショを撮ると「ロングスクリーンショットにしますか？」を表示。「はい」で自動スクロール撮影が始まり、「■ 停止」を押したところまで（または最下部まで）を1枚に合成 |
| 電源 + 音量下 | 同上（システムのスクリーンショット全般に反応します） |
| **3本指で下にスワイプ**（実験的・初期OFF） | 通常のスクリーンショット |
| **3本指で上にスワイプ**（実験的・初期OFF） | ロング（スクロール）スクリーンショット |
| **クイック設定タイル** | 通知シェードを閉じてからワンタップで撮影 |

- 保存先: `Pictures/Screenshots`（Google フォトの「スクリーンショット」に表示されます）
- ファイル名は `3FS_LongScreenshot_日時.png`
- **INTERNET 権限なし** — 画像が外部に送信されることは一切ありません

## セットアップ手順（初回のみ）

1. APK をインストールしてアプリを開く
2. **設定 → アプリ → 3本指スクショ → ︙ → 「制限付き設定を許可」**
   （Android 13+ では、ストア外アプリのユーザー補助は先にこれを許可しないと ON にできません）
3. アプリの「ユーザー補助の設定を開く」→ **3本指スクショ** → ON（フルコントロールを許可）
4. アプリの **「写真へのアクセスを許可」** を押して許可（背面タップ連携の検知に必要）＋通知の許可
5. **設定 → システム → ジェスチャー → クイックタップ** を ON にして「スクリーンショットを撮る」を選択
6. 背面を2回タップ → ポップアップの「はい」で動作確認

### 使い方

背面を2回タップ → 画面下の **「ロングスクリーンショットにしますか？ [はい] [✕]」**（8秒で自動的に消えます）
→ **はい** → Pixel 標準のプレビューが消えてから自動スクロール開始
→ 好きなところで **「■ 停止」** をタップ → 合成された1枚が保存されます

撮影結果（高さ・ページ数・終了理由）はアプリ画面の「直近のロングスクショ」と保存通知で確認できます。

## 仕組み

### 背面タップ連携
システムがスクリーンショットを保存したことを `MediaStore` の変更通知で検知し、
ユーザー補助のオーバーレイ（`TYPE_ACCESSIBILITY_OVERLAY`）で確認ポップアップを出します。
**タッチ入力には一切介入しない**ため、端末の操作感に影響しません。

### ロングスクリーンショットの合成
1. `AccessibilityService.takeScreenshot()` で撮影（root や画面録画の常駐通知は不要）
2. ゆっくりしたドラッグを注入してスクロール（慣性スクロールを避けるため、
   最後に指を止めてから離す2段階ジェスチャー。失敗時は `ACTION_SCROLL_FORWARD` にフォールバック）
3. 再撮影し、前フレームと**行ごとの輝度シグネチャ**を突き合わせて実スクロール量を推定
4. 新しく現れた部分だけを切り出して連結。「停止」・最下部・上限（30ページ / 高さ20,000px）まで繰り返す

**固定ヘッダー / 固定フッターの自動検出**: 最初のスクロール後に前後フレームを行単位で比較し、
動かない上端・下端（アプリバー、下部の入力バー等）を検出します。検出した領域は
スクロール量の推定から除外し、合成時は**ヘッダーを先頭に1回、フッターを末尾に1回だけ**描画します。
これを行わないと、固定バーが繰り返し継ぎ足されるうえ、「前後の画面が同じ＝最下部」と
誤判定して1スクロールで停止してしまいます。

**写り込み対策**: 撮影の瞬間は自前のオーバーレイを非表示にし、
Pixel 標準のスクショプレビュー（サムネイル＋共有/編集ボタン）が消えたことを
SystemUI のウィンドウから確認してから撮影を開始します。撮影中はトーストを使いません。

### 3本指ジェスチャー（実験的）
Android 13+ の `TouchInteractionController` を使い、タッチ開始から最大 70ms 様子を見て
3本指が揃えば自前で判定、それ以外は `requestDelegating()` で即座に通常の入力パイプラインへ委譲します。
構造上わずかなタップ遅延が生じるため**初期状態は OFF**で、アプリ内のスイッチで切り替えます。

> フレームワーク標準のマルチフィンガージェスチャー検出（`FLAG_REQUEST_MULTI_FINGER_GESTURES`）は、
> 1本指操作を守るための全画面パススルー領域と両立できません
> （パススルー領域内で始まったタッチはジェスチャー検出ごとスキップされる仕様）。

## ビルド

Android Studio でこのフォルダを開くか、Android SDK があれば:

```bash
cd pixel-three-finger-screenshot
./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk
```

- compileSdk 34 / minSdk 30 / targetSdk 34 / Kotlin 1.9 / 依存は kotlinx-coroutines のみ
- **署名**: `signing/debug.keystore` の固定キーで署名します。CI の使い捨て環境が毎回別の鍵を
  生成すると署名不一致で上書きインストールできなくなるため、リポジトリ内の鍵に固定しています
  （個人利用のサイドロード用途。公開配布用ではありません）

### CI

`.github/workflows/three-finger-screenshot-apk.yml` が push のたびに APK をビルドし、
Actions の Artifacts とサーバー（`app/three-finger-screenshot.apk`）へアップロードします。
スマホのブラウザでその URL を開けば上書きインストールでき、設定は保持されます。

## 制限・注意事項

- **3本指ジェスチャーには Android 13 以降が必要**です（`TouchInteractionController` API のため）。
  Android 11〜12 では背面タップ連携・クイック設定タイル・アプリ内テストボタンが使えます。
- **TalkBack などジェスチャーを使う他のユーザー補助サービスとは併用できません。**
- 銀行アプリなど `FLAG_SECURE` が設定された画面は撮影できません（Android の仕様）。
- 動画やアニメーションが再生中の画面、同じ模様が延々と続く画面では継ぎ目が乱れることがあります。
- 背面タップ連携には写真へのアクセス許可が必要です（保存されたスクリーンショットの検知のみに使用）。

## プロジェクト構成

```
app/src/main/java/com/okunukino/threefingershot/
├── ScreenshotAccessibilityService.kt  # サービス本体: 撮影・保存・通知・各機能の統合
├── ScreenshotWatcher.kt               # システムのスクショ保存をMediaStoreで検知
├── OverlayController.kt               # 確認ポップアップ／停止ボタンのオーバーレイ
├── LongScreenshotCapturer.kt          # 自動スクロール＋固定領域検出＋画像スティッチング
├── ThreeFingerGestureDetector.kt      # TouchInteractionControllerによる3本指検出
├── ScreenshotSaver.kt                 # MediaStore への保存
├── ScreenshotTileService.kt           # クイック設定タイル
├── Prefs.kt                           # 設定と直近の撮影結果
└── MainActivity.kt                    # 設定・テスト用画面
```
